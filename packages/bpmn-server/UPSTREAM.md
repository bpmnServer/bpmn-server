# The embeddable engine: the changes on this branch

The changes that make BPMN Server embeddable (by MDE applications, or any host): storage and locks behind ports, independent servers, lifecycle, timers owned and claimed across processes, errors as themselves. They were made and proven in the MDE repository (`AI-MDE/mdex`, `vendor/bpmn-server`), and are brought here on `feature/embeddable-engine`, from `master` at `bc96da2`. Each change below can be its own pull request.

## Changes, by the pull request each would be

1. **No process-wide error handler.** The upstream installs `process.on('uncaughtException')` when it is imported; an embedded engine leaves that to its host.
2. **Independent servers.** No static singleton inside the engine: each server has its own engine, cache, listeners, timers and connections, and several run in one process. `BPMNServer.getInstance()` and `BPMNServer.engine` are kept, deprecated: they answer the most recently constructed server not shut down.
3. **Lifecycle.** `server.ready` (and `BPMNServer.create(...)`) say when the server has started or why it could not; `shutdown()` stops it once however often called: new calls refused, timers cancelled, running executions given `shutdownTimeout` to finish, cache, listeners and subscriptions cleared, connections closed. `onLifecycle(listener)`: notifications awaited in order, a failing subscriber reported and isolated (`interfaces/lifecycle.ts`). Engine events go through `Listener.dispatch`, so subscribers are reached (the upstream's `Listener.doEvent` was never called).
4. **The storage port** (`interfaces/storage.ts`): `IDocumentStore`, the MongoDB operations the engine uses (find, insert, update, remove, createIndex, close), with `DuplicateKeyError` for a unique-index conflict and only for it. MongoDB is its default adapter; `MemoryDocumentStore` is another (tests, a standalone engine), and any other plugs in through the configuration's `documentStore` without changing engine code (the MDE adapter's PostgreSQL store is one). `DocumentQuery` is the shared semantics of the non-MongoDB adapters; an operator one does not know is refused, never ignored.
5. **The lock port** (`ILockManager`): an owner identity per process (`serverId`, else `SERVER_ID`, else host, process id and a random suffix); a duplicate key is contention, any other failure is thrown, not retried as if the lock were busy; release only by the owner; a lock older than `locks.staleAfter` taken over; `claim(key)` for one-time work across processes. The configuration's `locker` replaces it. The data store's locker reads its `db` when used, so a `db` replaced after the data store was made (as the upstream's tests do) is the one locked in.
6. **Typed data-store operations.** `updateInstanceSource` (the engine's `upgrade` no longer writes MongoDB itself; its `$nor` query is fixed: it was `elemMatch`, without the `$`); `saveInstance` awaits each write (the upstream kept every update promise in one array for the life of the store) and saves the version it is at (0 when first saved, one more each save).
7. **Timers** owned by the server: scheduled once per key, cancelled with the server or the instance, longer than `setTimeout` allows waited out in steps; before firing, claimed (one server fires a timer), and an item timer fires only while its item still waits; `timers.pollInterval` re-reads the waiting timers so another server fires those of a server that stopped. A forced delay (`timers.forceTimersDelay`) gives the timer a due time (the upstream left it undefined). The static counter is now per server (`cron.counters`).
8. **Errors.** A failed call is thrown to its caller as itself (the upstream wrapped it in a new `Error` from the logger, after which the `process.exception` event never ran); the execution is dropped from the cache; an invoke of an item that has ended is refused (`ItemNotWaitingError`), under the instance's lock, so two completions of one task do not both advance it. `Logger.reportError` honours `toConsole`.
9. **Cancellation.** `engine.cancel(query, user)`: the instance's tokens terminated, its timers cancelled, `process.terminated` emitted, saved as `terminated`; never deleted.
10. **Model files.** Written whole (a temporary file, then renamed), after the model has parsed; a missing SVG is `null`; a missing model is an error naming it; `rebuild` awaits its deletions.
11. **A called process ends its caller in turn.** When a called process ends (later than its own start), the caller's call activity is invoked, and awaited, before the called process's call returns; the upstream did it in the background (`Execution.end` did not await `CallActivity.executionEnded`), so whether the caller had moved on when the call returned was a race (bpmn-web's CallTask scenario passed or failed by timing). A called process that ends within its own start leaves it to the call activity, which continues at once.
12. **Security bypass per user.** `REQUIRE_AUTHENTICATION=false` / `ENFORCE_SECURITY=false` turned the API's security rules off for the whole process, from the first `SecureUser` made, and never back (a module-level flag); now each user's own, decided when it is made (`new SecureUser(info, { enforceSecurity })`, else the environment). The unused duplicate `API/AccessManager.ts` is removed.
13. **Re-entrant calls refused.** An engine call on an instance from within a call that holds it (a service task, script or listener calling the engine back on its own instance) waited for its own caller's lock until the tries ran out (30 s by default); now refused at once (`ReentrantCallError`), the held instances followed through the call with `AsyncLocalStorage`.
14. **Services called as methods.** A service task's implementation is called with its provider as `this` (it was called unbound).
15. **Paged search on any store.** `DataStore.find` on an adapter other than MongoDB answers as the aggregation does (`DocumentPager`); the aggregation now uses the instances' database (it named the server configuration's `db`, which does not exist, so it used the URL's default database), and no longer prints its pipeline.
16. **No barrel imports inside the engine.** Each module imports what it uses from the module that defines it, not through `index.js` files (the cycles through the barrels are gone); the barrels remain the package's public entry points. An unused module-level sort, with its shared maps, is removed from `Definition`.
17. **Behaviours** (`BehaviourLoader.register`) are documented as the library's, for every server in the process, as a moddle extension is.
18. **A message's one receiver comes first.** `throwMessage` delivers to a waiting instance before trying the start events (the upstream tried the start events first, so a waiting instance could be passed over for a new one); it passed the element id as the starting user. `waitingFor(kind, name, query)` is every item waiting for a message or signal.
19. **Signal throws are awaited.** The signal behaviour called `appDelegate.signalThrown` without awaiting it, unlike the message's: the delegate's work could finish after the instance was saved, and its failure was unhandled.
20. **Item queries.** `QueryTranslator` threw on a dotted path (`items.a.b`) into an item without `a`; its `$exists: false` never held.
21. **A named instance.** `engine.start` takes `options.instanceId`: the caller may name the instance, so an application's own record of it (MDE's work item) shares its id.
22. **Configuration.** A factory not given keeps its default (the upstream's constructor set it to `undefined`); new settings: `documentStore`, `locker`, `serverId`, `locks`, `shutdownTimeout`, `timers.pollInterval`.

## Tests

`test/scenarios/`: **bpmn-web's feature scenarios** (its mocha suite, `src/test/feature`, with its models and delegate), moved here to ship with the engine: `npm run test:scenarios` (MongoDB: `BPMN_TEST_MONGO_URL`, default the local server; a database of their own, `bpmn_scenarios`, emptied first). 313 passing, 10 pending, as in bpmn-web, on fresh and reused databases. Their delegate is plain JavaScript (`test/scenarios/app/`), without bpmn-web's mail, HTTP and template libraries; three scenarios declare variables they had assigned undeclared.

`test/` (ours): the engine on the in-memory store (a workflow end to end, recovery across servers, cancellation, versions, locking, timers, lifecycle, shutdown, upgrade, model files, the query semantics), and on MongoDB (`test/mongo.integration.test.mjs`, with `BPMN_TEST_MONGO_URL`). Build first: `npm run build` (the engine uses TypeScript enums, which Node does not strip). The upstream's own regression tests are to be run against this code before the upstream pull requests.
